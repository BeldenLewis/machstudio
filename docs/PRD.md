## 1. 제품 개요

**mach studio는 우리 마케팅팀 전용 웨비나 퍼널 운영 도구다.**
광고로 트래픽을 만들고 → 사전등록으로 리드를 모으고 → 웨비나로 전환시키고 → 결과를 분석하는 전체 사이클을 한 곳에서 운영한다.

- **형태**: 자체 호스팅 웹앱 (Next.js 16 / React 19 / Prisma 7 / Supabase Postgres / Vercel)
- **프로덕션**: machstudio.vercel.app (main 브랜치 자동 배포)
- **사용자**: 마케팅팀 내부 구성원만 (외부 판매 없음). 시청자·등록자는 공개 페이지로만 접촉.

### 1.1 왜 만들었나 (문제 정의)

| 기존 문제 | mach studio의 해결 |
|---|---|
| 웨비나 도구·폼 빌더·광고 리포트·UTM 시트가 전부 흩어져 있음 | 퍼널 전 단계를 단일 워크스페이스로 통합 |
| 외부 웨비나 SaaS는 비싸고 브랜딩·데이터 통제가 안 됨 | 등록→시청→설문까지 자체 페이지, 데이터는 우리 DB에 |
| 광고 성과와 웨비나 전환을 잇는 기여 분석이 수작업 | UTM 일원화 + 등록·참석·전환 액션 자동 연결 |
| 라이브 운영(투표·공지·Q&A)이 여러 툴에 분산 | 라이브 콘솔 하나로 실시간 운영 |

### 1.2 비전 문장

> "캠페인 기획부터 웨비나 종료 후 전환까지, 마케터가 다른 탭을 열 필요 없는 도구."

## 2. 사용자와 역할

### 2.1 내부 사용자 (팀)

| 페르소나 | 주 사용 화면 | 핵심 과업 |
|---|---|---|
| **캠페인 담당** | 광고성과, UTM 빌더, 대시보드 | 성과 데이터 반입, ROAS 추적, 링크 생성 |
| **웨비나 운영자** | 웨비나(만들기·배포·운영), 라이브 콘솔 | 등록 페이지 셋업, 리마인더, 라이브 진행 |
| **리드/CRM 담당** | 사전등록(collect), 등록자 탭 | 수집 소스 관리, 정규화·중복 정리, CSV 내보내기 |
| **팀 리드** | 대시보드, 분석, 공유 링크 | 주간 지표 확인, 경영 공유용 리포트 |

- 역할 구분: Workspace OWNER / ADMIN / MEMBER. 파괴적 작업(등록자 일괄삭제·내보내기)은 MEMBER 이상 + 확인 단계.
- 실제 팀 규모 ~3명 → 권한보다 **오조작 방지**(확인 모달, 미리보기)가 우선.

### 2.2 외부 접점 (비로그인)

- **시청자/등록자**: 공개 웨비나 페이지(등록 → 대기 → 입장확인 → 라이브 → 종료/설문). 계정 없음, 등록 정보로 식별.
- **공유 링크 수신자**: `/share/*` 읽기 전용 대시보드·분석 (토큰 기반).

## 3. 목표 / 비목표

### 3.1 목표 (v1 완료 기준 포함)

1. **퍼널 통합 운영** — 방문→등록→참석→전환 4단계를 단일 데이터로 연결 ✅
2. **웨비나 풀 사이클** — 등록 페이지 빌더, 리마인더, 라이브 콘솔(투표·공지·팝업·Tally·Q&A·채팅), 자체 설문, 다시보기 ✅
3. **광고 기여 분석** — 성과 CSV 반입(도달/전환 분류), UTM별 전환 기여 ✅
4. **저비용 운영** — Supabase Hobby egress 예산 안에서 동작 (폴링 단일화·캐싱·select 최소화) ✅
5. **모바일 대응** — 팀은 375px에서도 운영 가능, 시청자 페이지는 모바일 우선 ✅

### 3.2 비목표 (하지 않는다)

- 외부 고객 대상 멀티테넌트 SaaS 화 (과금, 온보딩 퍼널, 셀프서브)
- 이메일 마케팅 플랫폼 수준의 캠페인 빌더 (리마인더·알림 수준까지만)
- 실시간 스트리밍 인프라 자체 구축 (YouTube 임베드 유지)
- 네이티브 앱

## 4. 핵심 모듈별 요구사항

### 4.1 대시보드 (`/dashboard`)

- 워크스페이스 전체 KPI: 방문·등록·전환율·광고 성과 요약, 기간 비교.
- 자동 새로고침은 탭 활성(visibility) 시에만. 리포트 결과 캐싱.
- 위젯 구성은 `Dashboard`/`DashboardWidget` 모델 기반.

### 4.2 광고 성과 (`/analytics`)

- **성과 반입**: CSV import → `AdPerformanceImportBatch`/`AdPerformanceRecord`. 5,000행 상한.
- **결과 유형 분류**: `resultBucket`으로 도달(reach)/전환(conversion) 구분 — 도달 캠페인은 conversions=0으로 왜곡되지 않게 별도 표기.
- 지표: 지출, 결과 수, CPL, ROAS, CPM(도달형). 목표 대비 달성률.

### 4.3 UTM 빌더 (`/utm-builder`)

- source/medium/campaign 조합 → 링크 생성. 프리셋(`UTMPreset`)·템플릿(`UTMTemplate`)·숏링크(`ShortLink`).
- 입력은 소스에서 정규화(소문자·하이픈) — 팀 전체가 같은 네이밍 규칙 사용.

### 4.4 사전등록 / collect (`/collect`, `/collect/[id]`)

- **수집 소스**(`CollectSource`): 자사 폼, 외부 임베드, CSV/API 반입. 필드 매핑(`FieldMapping`).
- **레코드 관리**(`CollectRecord`): 목록·상세, 정규화(전화번호 등) 미리보기 후 적용, 중복 정리, GDPR 영구삭제(확인 단계 필수).
- **보존 정책**(`CollectRetentionPolicy`): 기간 경과 데이터 자동 정리.

### 4.5 웨비나 (`/webinar`, `/webinar/[slug]`) — 제품의 중심

어드민은 **4탭 허브**: 만들기 → 배포 → 운영 → 분석. 상태 연동 기본 진입(종료→분석, 라이브→운영, 그 외→만들기).

#### A. 만들기 (create)
- 기본 정보, 세션/연사(사진·세션유형), 등록 폼 빌더(커스텀 필드, consent 기본 OFF), 라이브 페이지 구성(STK 토큰 테마, CTA, 채팅 온오프), 자체 설문 빌더(별점·객관식·NPS·주관식, 자동저장+드래그 정렬), 준비 체크리스트.

#### B. 배포 (deploy)
- 공개 링크, 임베드(히어로 버튼·배너·폼 위젯) 스니펫, 부착 가이드, 허용 사이트(`WebinarEmbedSite`).

#### C. 운영 (operate)
- **라이브 콘솔**: 인터랙션 카드(투표·공지·팝업·Tally·알림발송 통합, 설정은 사이드 드로어), Q&A 모더레이션(추천순, 답변완료, 화면 노출), 채팅 모더레이션(천천히 모드, 링크 숨김, 금지어, 고정), 러닝오더(KST 절대시각), 상태 전환(수동 오버라이드, 라이브 전환은 확인 단계).
- **단일 활성 원칙**: 팝업/투표/Tally/Q&A 화면노출/채팅 고정은 웨비나당 1개만 활성 — DB partial unique index + P2002→409.
- **등록자 탭**: 목록(select 최소화), 검색, 일괄 삭제(확인), CSV 내보내기(UTM+커스텀 필드 포함), import(5,000행 상한).
- **리마인더**: 예약·발송, 60초 중복 발송 방지, 발송 전 확인.

#### D. 분석 (analytics)
- 퍼널(방문→등록→참석→전환), UTM 분해, 등록 추이, 시청 곡선(attendance-curve), 설문 응답.

#### E. 공개 시청자 페이지 (`/webinar/[slug]`, `/webinar/[slug]/live`)
- 상태 머신: 일정 기반 자동 + `statusOverride` 수동. 등록→대기(PreLiveWaiting)→입장확인(EntryVerify)→라이브(LiveContentStk: 영상+Q&A/채팅/세션 탭, 시청자수)→종료(EndedScreen: 다시보기·설문).
- **라이브 데이터는 `/live-state` 단일 폴링(12s)** — 새 폴러 금지, 필드 추가로 확장.
- 소유자 **미리보기 모드**(`?preview`): 4개 상태를 전환 바로 확인, 모든 부작용(추적·발송) `isPreviewUrl` 가드.
- 설문 공개 페이지(`/webinar/[slug]/survey/[surveyId]`), 종료 화면 자동 노출(showOnEnded).

### 4.6 공유 (`/share/*`)
- 토큰 기반 읽기 전용: 대시보드·분석. 로그인 없는 경영 공유용.

### 4.7 설정 (`/settings`, `/settings/workspace`)
- 프로필, 워크스페이스 멤버·초대, API 토큰, 알림 설정.

## 5. 비기능 요구사항

| 영역 | 요구사항 | 현재 상태 |
|---|---|---|
| **비용/egress** | Supabase Hobby 예산 내. 공개 라우트 payload 최소화, 폴링 단일화, config는 필요 시에만 | ✅ 감사 배치 B 완료 |
| **레이트리밋** | 웨비나 공개 라우트는 `rateLimitAsync`(Upstash Redis, 인메모리 폴백) | ✅ Redis 연결·Vercel env 설정 |
| **개인정보** | 공개 응답에 PII 미노출(이름 마스킹, email/phone 응답 제거), consent 기본 false, GDPR 삭제 | ✅ |
| **보안** | projectId 테넌트 격리, 등록 검증(registrationId 403), youtubeId 게이팅 | ✅ |
| **접근성** | 대비 4.5:1, focus-visible, ARIA tabs/radiogroup, reduced-motion 전역 | ✅ |
| **모바일** | 팀 화면 375px, 시청자 조작 컨트롤 터치타깃 ≥44px | ✅ |
| **검증 규율** | 배포 전 `npx tsc --noEmit` + `npm run build` 필수. DB는 db push(빈 migrations) — 스키마 변경 시 세션 URL로 execute | 운영 규칙 |

## 6. 성공 지표 (팀 내부 기준)

- **운영 효율**: 웨비나 1회 셋업~종료까지 외부 툴 0개 사용 (현재 달성)
- **퍼널 지표**: 방문→등록 전환율, 참석률, 참석→전환 액션률 — 대시보드에서 주간 추적
- **데이터 품질**: 완전 레코드 비율 95%+ 유지 (정규화·중복 정리)
- **안정성**: 라이브 중 콘솔·시청자 페이지 장애 0건

## 7. 로드맵 / 백로그

### 완료 (2026 Q3 현재)
등록 폼·커스텀 필드, 라이브 콘솔 전체 인터랙션, 자체 설문, 리마인더, 프리뷰 모드, 광고 반입·resultBucket, 임베드 배포, Redis 레이트리밋, 전면 감사(A~E 배치), 모바일 대응, PreLiveWaiting·시청자수·알림 옵트인.

1. **종료 후 전환 번들** — 종료 화면 CTA 고도화, 다시보기 페이지 자동 생성, 노쇼 리커버리 플로우
2. **리드·데이터 번들** — 세일즈포스/CRM 반출 연동, 리드 스코어링
3. **참여 강화 번들** — 라이브 리액션, 추첨/퀴즈
4. **데이터 카드 스켈레톤 통일** — 대시보드·분석 첫 로드 (UI 감사 잔여)

## 8. 운영 원칙 (요약)

- UI 원칙은 [AGENTS.md](../AGENTS.md) — 읽는/고치는/다루는 영역별 규칙이 하한선.
- 시청자 라이브 데이터는 live-state 단일 폴링. 새 부작용은 isPreviewUrl 가드.
- 파괴적 액션은 항상 커스텀 확인 모달(`useConfirm`, tone: danger) — native confirm 금지.
- 단일 활성 푸시는 DB 제약으로 보장, 코드에서 P2002→409 처리.
