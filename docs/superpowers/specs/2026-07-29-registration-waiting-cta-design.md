# 사전등록 완료 CTA·대기 화면 콘텐츠 개선 설계

작성일: 2026-07-29

## 목표

사전등록 폼의 체크박스와 문구 정렬을 모든 공개 경로에서 일관되게 고친다. 등록 완료 모달에는 운영자가 설정할 수 있는 CTA를 추가한다. 대기 화면에서는 현재 대기 인원 밴드를 실제 ON/OFF 설정과 연결하고, 밴드와 독립적으로 운영되는 안내문·CTA 영역을 추가한다.

## 범위

- 관리자 등록 폼 설정과 미리보기
- 자체 라이브 페이지의 사전등록 모달과 등록 완료 모달
- 외부 사이트 임베드 등록 폼과 등록 완료 팝업
- 관리자 대기 화면 설정
- 자체 라이브 페이지의 대기 화면
- 공개 설정 정규화와 임베드 설정 응답
- 관련 단위 테스트와 공개 화면 검증

## 설계 원칙

- 자체 페이지와 임베드가 같은 정규화된 설정을 읽는다.
- 공개 섹션은 ON 상태와 실제 데이터가 모두 있어야 노출한다.
- 대기 인원 밴드와 안내문·CTA는 서로 영향을 주지 않는 독립 영역이다.
- 공개 URL은 `http:` 또는 `https:`만 허용한다.
- 색상과 표면은 기존 STK 테마 토큰에서 파생한다.
- 모바일 터치 영역과 여러 줄 문구를 기준으로 정렬한다.

## 1. 사전등록 체크 항목 정렬

### 문제

자체 등록 모달은 브라우저 기본 체크박스에 위쪽 여백을 주고 있고, 임베드 폼과 관리자 미리보기는 서로 다른 체크박스 크기와 줄 높이를 사용한다. 문구가 한 줄일 때도 체크박스 중심과 글자 첫 줄의 중심이 어긋날 수 있다.

### 동작

- 체크박스는 고정 크기와 `flex: none`을 사용한다.
- 체크박스 높이와 문구 첫 줄 높이를 맞춘다.
- 여러 줄 문구에서는 첫 줄 기준으로 정렬한다.
- 개인정보·마케팅 동의와 사용자 정의 체크박스/복수 선택 행에 같은 기준을 적용한다.
- 클릭 가능한 약관 문구가 버튼일 때도 일반 텍스트와 같은 줄 높이를 유지한다.

### 적용 면

- `RegistrationFormTab`의 관리자 미리보기
- 자체 라이브 페이지 등록 모달
- `webinar-loader-script`가 만드는 임베드 등록 폼

## 2. 등록 완료 모달 CTA

### 설정

`config.registrationForm` 아래에 다음 설정을 추가한다.

```ts
successCta: {
  enabled: boolean;
  label: string;
  url: string;
}
```

기본값은 비활성, 빈 라벨, 빈 URL이다. 기존 웨비나는 현재 완료 모달을 그대로 유지한다.

### 관리자 UI

등록 폼 탭에 `등록 완료 화면` 영역을 추가한다.

- `CTA 표시` ON/OFF
- `버튼 문구`
- `연결 URL`
- URL이 유효하지 않으면 입력 바로 아래에 안내
- 완료 화면 미리보기에서 CTA와 닫기 위계를 확인 가능

편집 값은 펼침이나 별도 모달 뒤에 숨기지 않고 토글 옆에서 바로 수정한다.

### 공개 동작

- CTA는 `enabled === true`, 라벨 있음, 안전한 URL 있음 조건을 모두 만족할 때만 표시한다.
- CTA는 강조 버튼이며 새 탭으로 연다.
- 새 탭 링크에는 `noopener noreferrer`를 적용한다.
- 기존 확인/닫기 동작은 보조 버튼으로 남긴다.
- CTA가 유효하지 않으면 기존 단일 확인 버튼 화면으로 폴백한다.
- 자체 라이브 페이지와 외부 임베드 완료 팝업에 동일하게 적용한다.
- 기존 임베드 `components.formWidget.successMessage` 동작은 유지한다.

## 3. 대기 인원 밴드

### 기존 상태

`N명이 함께 기다려요` 밴드와 30초 주기의 실제 대기 인원 집계는 이미 구현되어 있다. 그러나 밴드 렌더가 `livePage.waiting.social` 설정을 확인하지 않아 관리자 토글과 연결되지 않았다. 별도의 레거시 등록자 총원 패널은 데이터가 전달되지 않아 노출되지 않는다.

### 동작

- 기존 `livePage.waiting.social`을 인원 밴드 ON/OFF의 단일 설정으로 사용한다.
- 관리자 라벨을 `함께 기다리는 인원 밴드`로 변경한다.
- 토글 ON, 마운트 완료, 현재 대기 인원 2명 이상일 때만 표시한다.
- 숫자는 기존 상태 API의 최근 5분 프레즌스 값을 사용한다.
- 0명·1명·집계하지 않는 구간에는 밴드를 숨긴다.
- 데이터가 없는 레거시 등록자 총원 패널과 관련 가짜 아바타 표현은 제거한다.
- 노출 상태 감사에서는 `broken` 판정을 제거하고 실제 조건을 설명한다.

## 4. 대기 안내문·CTA

### 설정

`config.livePage.waiting` 아래에 다음 설정을 추가한다.

```ts
followUp: {
  enabled: boolean;
  text: string;
  ctaLabel: string;
  ctaUrl: string;
}
```

기본값은 비활성 및 빈 값이다.

### 관리자 UI

대기 화면 설정에 `안내문·CTA` 영역을 추가한다.

- 독립 ON/OFF
- 줄바꿈 가능한 안내 문구
- 버튼 문구
- 연결 URL
- URL 오류는 해당 입력 아래에 인라인 표시

인원 밴드의 ON/OFF와 무관하게 편집하고 노출할 수 있다.

### 공개 동작

- 위치는 인원 밴드 자리 아래, 캘린더·공유·알림 같은 기능 버튼 위다.
- 밴드가 숨겨져도 안내 영역은 같은 위치에 독립적으로 표시한다.
- `enabled === true`이면서 안내 문구 또는 완성된 CTA가 있을 때만 영역을 표시한다.
- 안내 문구는 줄바꿈을 보존한다.
- CTA는 라벨과 안전한 URL이 모두 있을 때만 표시하고 새 탭으로 연다.
- 문구만 또는 CTA만 설정한 구성도 허용한다.
- 배경·텍스트·버튼 색은 STK 테마 토큰에서 파생한다.

## 데이터와 호환성

- Prisma 마이그레이션은 필요하지 않다. 두 기능 모두 기존 JSON 설정에 저장한다.
- 정규화 함수가 누락된 값을 기본값으로 채워 기존 웨비나를 보존한다.
- 등록 폼 임베드 설정 응답에 `successCta`를 명시적으로 포함한다.
- `/info`와 소유자 미리보기는 기존 allowlist의 `registrationForm`·`livePage`를 통해 새 값을 전달한다.
- 공개 렌더에서는 URL을 다시 검증하여 잘못된 스킴이 저장돼도 실행되지 않게 한다.

## 접근성·반응형

- 체크박스와 첫 줄 문구를 시각적으로 정렬하고 클릭 가능한 행의 터치 영역을 유지한다.
- CTA는 키보드 포커스가 보이고 최소 44px 높이를 유지한다.
- 새 탭 동작은 링크 요소의 의미를 보존한다.
- 완료 모달의 긴 안내 문구가 있어도 CTA와 닫기 버튼에 접근 가능해야 한다.
- 대기 안내문은 모바일에서 과도하게 넓어지지 않고 가운데 정렬을 유지한다.
- 기존 `prefers-reduced-motion` 처리를 존중한다.

## 오류 처리

- 관리자 URL 입력이 비어 있으면 오류가 아니라 CTA 미완성 상태로 취급한다.
- 값이 있으나 `http(s)` URL이 아니면 인라인 오류를 표시한다.
- 공개 화면에서는 유효하지 않은 CTA를 숨기고 나머지 콘텐츠는 정상 렌더한다.
- 대기 인원 조회 실패 시 밴드만 숨기고 안내문·CTA와 다른 대기 기능은 유지한다.

## 검증

- 등록 폼 정규화: 새 설정 기본값, 유효 값, 잘못된 URL 폴백
- 대기 화면 정규화: `social` 및 독립 `followUp` 기본값과 저장 값
- 대기 밴드: 토글 OFF, 0명, 1명, 2명 이상 조건
- 대기 안내: 밴드와 독립 노출, 문구만, CTA만, 불완전 CTA
- 등록 완료 모달: CTA 없음, 유효 CTA, 불완전/위험 URL
- 관리자 자동저장 payload에 새 설정 포함
- 자체 페이지와 임베드에서 새 탭·닫기 동작 확인
- 모바일 폭에서 체크 항목 정렬과 완료 모달 버튼 접근성 확인

## 제외 범위

- 완료 안내 문구 자체를 새 설정으로 이전하거나 편집 기능을 확대하지 않는다.
- 같은 탭/새 탭 선택 옵션은 만들지 않는다.
- 대기 인원 집계 방식과 5분 프레즌스 창은 변경하지 않는다.
- 범용 CTA 카드 빌더나 다중 CTA는 도입하지 않는다.
