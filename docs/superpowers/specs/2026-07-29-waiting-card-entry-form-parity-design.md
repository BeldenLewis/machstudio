# 대기 화면 카드·캘린더 배너·입장 등록 폼 통합 설계

## 배경

현재 대기 화면의 `캘린더에 추가`는 공유·알림과 같은 작은 버튼 행에 있고, 새 안내 CTA는 카운트다운 바로 아래에 떠 있다. 사용자가 기대한 구조는 랜딩의 모바일 배너와 `이 웨비나는` 카드 열을 재사용하는 것이다.

입장 확인 화면에서 `사전등록하기`를 눌렀을 때 열리는 React 폼은 랜딩 로더가 그리는 공개 등록 폼과 별도로 구현돼 있다. 같은 설정을 읽더라도 마크업·스타일·선택형 필드·동의 영역이 서로 달라질 수 있다.

## 목표

1. 대기 화면의 캘린더 CTA를 모바일 전용 하단 배너로 바꾼다.
2. 대기 안내문과 CTA를 `이 웨비나는` 소개 카드 아래에 추가되는 별도 카드로 바꾼다.
3. 입장 화면의 사전등록 모달을 랜딩 공개 등록 폼과 같은 UI·동작으로 통합한다.
4. 기존 설정 데이터와 공개 URL은 그대로 호환한다.

## 화면 설계

### 모바일 캘린더 배너

- `waiting.calendar`가 켜져 있고 유효한 캘린더 동작이 있을 때만 표시한다.
- 600px 이하에서 화면 하단에 고정된 배너로 표시한다.
- 구성은 랜딩 배너와 동일하게 짧은 안내 문구와 `캘린더 추가` 버튼 한 개다.
- 배너의 모양·간격·블러·그림자·전환은 랜딩 배너 패턴을 따른다.
- 색은 공개 시청 화면 규칙에 맞춰 STK의 `accent/text/surface` 파생 토큰만 사용한다.
- 데스크톱에서는 캘린더 CTA를 표시하지 않는다.
- 공유와 시작 알림은 기존 인라인 버튼 행을 유지하며, 캘린더가 빠져도 빈 컨테이너를 만들지 않는다.
- 모바일 안전 영역을 포함하고, 화면의 주요 버튼이나 모달이 열리면 겹치지 않게 숨기거나 여백을 확보한다.

### `이 웨비나는` 추가 카드

- 카운트다운 아래의 기존 `plw-follow-up` 문구·버튼 UI는 제거한다.
- 왼쪽 열의 기존 `이 웨비나는` 소개 카드 바로 아래에 별도 카드를 쌓는다.
- 카드에는 저장된 안내 문구를 줄바꿈 그대로 표시하고, 유효한 `label + URL`이 모두 있을 때만 CTA 버튼을 표시한다.
- CTA는 새 탭으로 연다.
- `followUp.enabled`와 실제 문구 또는 유효 CTA가 모두 있을 때만 카드를 표시한다.
- 인원 밴드와 완전히 독립적으로 동작한다.
- 아젠다가 꺼져 있어도 추가 카드가 켜져 있으면 `이 웨비나는` 열은 표시한다. 이 경우 빈 오른쪽 열을 만들지 않는다.
- 관리자 설정 이름은 `안내문 · CTA`에서 `이 웨비나는 추가 카드`로 바꾸고, 실제 배치가 드러나는 설명을 붙인다.

## 입장 화면 등록 폼 통합

- 입장 확인 카드의 `사전등록하기`는 현재 페이지를 떠나지 않고 모달을 연다.
- 모달은 랜딩 공개 등록 폼과 같은 카드 폭, 제목, 라벨, 입력, 선택형 필드, 체크박스, 동의 문구, 오류, 제출 버튼 스타일을 사용한다.
- 두 화면이 같은 `normalizeRegistrationForm` 결과와 같은 공개 폼 스타일 계약을 사용하도록 공용 모듈을 둔다.
- 전화번호 숫자 정규화, 필수값 검사, 복수 선택 상한, 기타 직접 입력, 이메일·전화번호 중복 확인, 약관 전문, 제출 중 상태를 동일하게 유지한다.
- 등록 완료 문구와 설정된 완료 CTA도 랜딩과 같은 위계로 표시한다.
- 모달은 모바일에서 본문만 스크롤되고 닫기와 제출 동작에 접근할 수 있어야 한다.
- Escape, 포커스 트랩, 닫은 뒤 포커스 복원을 지원한다. 등록 성공으로 원래 버튼이 사라지면 새 등록 완료 상태의 안정적인 CTA 또는 제목으로 포커스를 넘긴다.

## 데이터와 호환성

- 기존 `livePage.waiting.followUp`의 `enabled`, `text`, `ctaLabel`, `ctaUrl`을 그대로 사용한다.
- `waiting.calendar`, `calendarUrl`, 등록 폼 설정 계약을 유지한다.
- 데이터베이스 마이그레이션과 기존 저장값 변환은 필요 없다.
- 빈 데이터는 토글이 켜져 있어도 공개 화면에 노출하지 않는다.

## 검증

- 375px에서 캘린더 배너가 보이고 1440px에서는 보이지 않는 렌더 테스트를 추가한다.
- 공유·알림만 켠 경우와 캘린더 데이터가 없는 경우 빈 CTA 영역이 생기지 않는지 검증한다.
- 추가 카드가 소개 카드 다음에 렌더되고, 인원 밴드 및 아젠다 토글과 독립적인지 검증한다.
- 입장 화면 사전등록 모달이 랜딩 폼의 필드 순서·선택형 필드·동의 영역·오류·제출·완료 CTA를 동일하게 제공하는지 검증한다.
- 등록 성공 후 사라진 원래 버튼 대신 안정적인 대상에 포커스가 남는지 검증한다.
- 집중 테스트, 전체 테스트, 타입 검사, 빌드와 모바일·데스크톱 브라우저 확인을 수행한다.
