## 1. 절대 규칙 — 어기면 실제 서비스가 죽는다

1. **로컬 dev 와 프로덕션이 같은 DB 다.** 웨비나 방송 중 로컬 dev 서버를 띄우면 커넥션 풀(200)을
   먹어 실제 장애가 난다(2026-08-11 실사고). 방송 일정을 모르면 dev 서버·DB 스크립트 실행 전에
   사용자에게 확인하라.
2. **`prisma db push` 금지.** 부분 유니크 인덱스 10개(스키마에 표현 불가)를 소리 없이 지운다.
   마이그레이션은 세션 URL(:6543→:5432) + `prisma db execute`, 그 후
   `node scripts/ensure-partial-unique-indexes.mjs` 로 점검(--apply 로 복원). dev 스키마 동기화가
   필요하면 push 후 **반드시** ensure 스크립트를 돌려라.
3. **연동형(capture) 사전등록 3개 소스 = 레코드 52,000건.** `/api/collect` 경로·fieldMappings 소비처는
   한 글자도 동작이 바뀌면 안 된다. `collectColumnsFor` 는 capture 에 대해 저장값을 **같은 참조로**
   통과시킨다(테스트가 참조 동일성을 단언).
4. **남의 PR 을 임의로 머지하지 마라.** hook-lee(대회 담당)가 병행 작업 중이다. 병합은 사용자 지시로만.
5. 결제·플랜(Supabase/Vercel/Resend)은 사용자가 직접 한다. 안내만 하라.
6. 프로덕션 DB 에 쓰는 검증이 필요하면: **이름에 `[임시검증]` 을 붙인 임시 소스**를 만들어 거기에만
   쓰고, 끝나면 트랜잭션으로 지워라(선례: §3 의 E2E). 운영 소스에는 절대 쓰지 마라.

## 3. 작업 큐 — 우선순위 순

### A. IA 검토 생존 결함 5건 (승인됨 — 바로 착수 가능)

메뉴 재편은 **하지 않는다**(검토 결론: 32제안 중 25 기각, 구조는 유지). 아래 5건만 고친다.

1. **[high] 딥링크가 남의 전시 공개 페이지를 바꾼다.**
   `src/app/(app)/webinar/[slug]/DeployTab.tsx` :243(목록 fetch)·:275(사이트 생성)가 사이드바의
   `currentProject.id` 를 쓴다 — URL 의 웨비나와 사이드바 프로젝트가 다르면 **다른 전시의 아임웹
   사이트 목록**이 뜨고, '전환' 버튼이 그 사이트의 `activeWebinarId` 를 바꾼다(성공 토스트까지 뜸).
   수정: ① DeployTab 에 `projectId` prop 추가(허브 `page.tsx` 가 이미 `webinar.project` 보유) 후
   `currentProject.id` 두 곳 교체 ② 서버 방어 — `src/app/api/webinar-embed-sites/route.ts`(POST)와
   `[id]/route.ts`(PATCH, :64 부근)에 `site.projectId === webinar.projectId` 검증(아니면 400).
   ③ 배포 전 교차 프로젝트 사이트가 이미 있는지 1회 조회(있으면 사용자에게 보고).
   ※ 사이드바 동기화 이펙트 이식·대회 브레드크럼은 **하지 마라** — 반론 검토에서 기각됨.

2. **[high] 스니펫 주소를 브라우저 주소창에서 만든다.**
   `src/app/(app)/collect/[id]/FormBuilderTab.tsx` :177·:260, `src/app/(app)/competition/[slug]/DeployTab.tsx` :48
   의 `window.location.origin` → `getPublicAppOrigin()`(`src/lib/app-url.ts`) 교체. 프리뷰/localhost 에서
   복사한 코드가 파트너 사이트에 박히면 곧 죽는 주소다. 그리고 **eslint 로 강제**:
   `eslint.config.mjs` 에 `(app)` 하위 `window.location.origin` 금지(no-restricted-syntax) — 예외는
   eslint-disable + 이유 주석. (줄 번호는 hook-lee 변경으로 밀렸을 수 있다 — grep 으로 다시 찾아라.)

3. **[high] 빌더형 첫 화면이 없는 탭을 지시한다.**
   `src/app/(app)/collect/[id]/page.tsx` ~:1202 빈 상태 「스크립트를 설치하면…」에 mode 분기 —
   빌더형에는 스크립트 탭이 없다(`tabs.ts` CAPTURE_ONLY). builder 면 「등록 폼 탭에서 폼을 만들고
   코드를 붙이면 여기 쌓여요」. 문구 분기만, 진입 탭 변경은 하지 않는다(기각됨).

4. **[high] 수집 데이터 검색이 등록번호를 못 찾는다.**

   `registrationNo` 는 최상위 컬럼이라 안 걸린다. 현장 접수대에서 티켓 번호 조회가 안 되는 문제.

5. **[medium] 안내 문구가 사라진 메뉴를 가리킨다.**
   `LiveConsoleTab.tsx` :1041·:1133·:459, `LivePageTab.tsx` :555 — IA 재편 전 메뉴 이름 4곳을

6. **AGENTS.md 에 "새 면을 만들 때" 절 추가** (5건의 구조적 원인 봉인):

```bash
npx tsc --noEmit
npx vitest run --exclude '.worktrees/**' src
```

번들 소스를 만졌으면 재빌드 후 테스트(stale 검사가 잡는다). 신규 코드는 lint 클린으로(기존 123건에
보태지 말 것). 커밋 메시지는 한국어·왜-중심, `Co-Authored-By` 트레일러 유지. main 직푸시 가능하지만
기능 단위는 브랜치+PR 이 관례다.
